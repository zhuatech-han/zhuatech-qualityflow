# QualityFlow 部署与升级

知华科技（上海如静知华信息科技有限公司） · [官网](https://www.zhuatech.cn/) · 商业咨询微信 zhuatech / zhuatech2。

## 环境与第一次启动

支持 Java 21、Maven 3.9、Node.js 24.19.0、MySQL 8.4；完整本机学习环境建议 Docker Compose v2。凭证生成需要 Python 3.10+。前端镜像使用 Node 构建、Nginx 运行；后端镜像构建执行格式检查与全部测试，不跳过测试，依赖缓存使用共享锁、预取与三次重试。

```sh
python3 scripts/init-env.py
docker compose config --quiet
docker compose up -d --build --wait
```

脚本以排他方式创建权限 `0600` 的 `.env`，为数据库应用账号、数据库 root 和初始管理员分别生成随机强密码。不要公开或提交它。访问本机 `http://127.0.0.1:8098`，用 `admin` 和其中的 `ADMIN_PASSWORD` 登录。账号与 BCrypt 散列只在空库生成，后续改变环境值不会重置已有账号。

Compose 的数据库名为 `zhuatech_qualityflow`，账号为 `qualityflow`，MySQL 卷为当前 Compose 项目名下的 `mysql-data`。数据库与后端端口不暴露到主机。前端 `WEB_PORT`、`BIND_ADDRESS` 可覆盖；默认本机监听。多个项目用不同 Compose 项目名、端口和配置，勿共享业务卷。

后端等待 MySQL 健康，前端等待后端健康；`docker compose ps` 应显示健康。`/actuator/health` 是唯一公开监控端点。重启应用不会删库，正常停止使用 `docker compose down`，需要保留业务时不要附加 `-v`。

## 数据迁移

Flyway 顺序执行 `V1__quality.sql`、`V2__quality_indexes.sql`、`V3__event_text.sql`。V1 创建组织、权限与质量业务，长描述和证据字段使用 TEXT，接口仍按业务长度校验；V2 补充索引及导航权限外键；V3 将事件说明扩展为 TEXT，保留长度上限内两项文本组合后的完整历史。JPA 启动只验证结构，不自动建表改表。

升级应先备份数据库和本地配置，再获取目标版本、检查新增迁移、构建并启动。已发布迁移不得修改。启动会校验旧迁移校验和，成功后应用新版本。迁移失败先记录错误、查明原因并恢复备份或使用经过评审的新迁移；不要在真实库中直接删除 Flyway 历史或数据卷。

本版验证涵盖全新库结构迁移和带既有业务数据的版本 2→3 升级，以及应用重启后的既有记录、事件和管理员密码保持。没有更早业务版本的跨版本兼容承诺。

## HTTPS 与正式使用准备

商业使用须先获得书面授权。部署方负责管理访问入口、数据库备份、账号权限与恢复演练。默认配置是本机学习环境。

- 使用可信 HTTPS 入口并设置 `COOKIE_SECURE=true`。Nginx 代理传递协议；在外部反向代理终止 TLS 时，需明确受信任代理和实际 HTTPS 协议处理，避免 Secure Cookie 配置错误。
- MySQL Connector/J 默认使用 `sslMode=trust` 加密连接，但不校验 CA 与主机名。正式环境使用可信 CA，并按 MariaDB Connector/J 官方说明配置 `verify-full`、证书与实际主机名；不要把数据库密码放进 URL。
- `DATABASE_CATALOG` 必须与实际库名一致。驱动使用 MariaDB Connector/J 3.5.10，连接目标仍为 MySQL 8.4，JPA 使用 MySQLDialect。
- 限制数据库网络访问和应用账号权限；日志不记录密码或完整请求载荷。保留 `org.hibernate.orm.connections.pooling=OFF`，避免连接配置被 Hibernate 启动信息打印。
- 本版单实例会话和登录失败窗口在内存中。扩容、多租户、统一身份、集中限流、持久会话和防篡改审计需要另行设计。
- 后端运行镜像基于官方 Maven / Java 21，采用非 root 账号，包含构建工具，镜像体积较大。正式交付可经验证改为专用 Java 运行镜像并保留全部验收门槛。

## 验收库与清理

只在专用的可销毁学习部署执行：

```sh
docker compose -p qualityflow-check up -d --build --wait
python3 scripts/smoke.py --allow-test-data
```

脚本只接受本机地址与明确测试标记，会建立虚构验收部门、账号和质量问题。需要指定不同端口时配置 `.env` 并传 `--base http://127.0.0.1:端口`。它不清理业务记录，测试完成后仅对**本次专用部署**执行：

```sh
docker compose -p qualityflow-check down -v
```

不要对其他项目或真实业务部署执行销毁命令。浏览器验收凭证只能临时写入仓库外的受限文件，完成后删除。

## 故障定位

| 情况 | 检查 |
| --- | --- |
| Compose 拒绝解析 | 必填的三个密码是否设置，端口是否有效 |
| MySQL 不健康 | 专用卷状态、磁盘空间、初始化日志；旧库密码不会因环境值自动改变 |
| 后端不健康 | 数据库连接名、数据库真实密码、Flyway 错误与 JPA 字段验证 |
| 登录失败 | 初始密码来自首次空库配置；检查停用状态，勿猜测固定密码 |
| 浏览器请求失败 | 前端 Nginx 代理、后端健康、HTTPS 与 Cookie 配置 |
| 版本过期 | 刷新业务详情，以新版本操作；原请求重试应保持原请求键和内容 |

第三方配置与许可证见第三方说明；部署咨询微信 zhuatech / zhuatech2。
