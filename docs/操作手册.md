# QualityFlow 操作手册

知华科技（上海如静知华信息科技有限公司） · [官网](https://www.zhuatech.cn/) · 商业咨询微信 zhuatech / zhuatech2。

## 建立协作账号

管理员首次登录后创建部门和人员。通常使用“质量协调员”报告问题、“整改执行人”负责整改或执行措施、“质量复核人”负责独立复核。新建或重置密码须 12–72 位，包含大小写字母和数字。不要把初始管理员凭证发给所有人员。

角色包含功能权限和三种数据范围。本人关联范围的执行人员只看参与的记录，部门范围的协调员和复核人看本部门，管理员看全部。修改角色或停用账号会在下一次请求生效。保留一个启用且范围为全部数据的管理员。

## 从报告到关闭

1. 在“我的待办”或“质量问题”点击“报告质量问题”，填写描述、来源、类别、严重度、关联凭证和截止日，选择同部门的整改责任人及独立复核人。复核人不能是报告人或整改责任人。
2. 保存为草稿后可修改或删除。提交报告后冻结标题、描述与归属。报告人在待处置阶段可带理由取消；开始处置后不能取消或删除。
3. 整改责任人在待办中登记临时处置与影响范围，进入“原因与方案”。保存原因分析、效果验证方法和最早效果验证日；在此阶段也可带理由调整截止日。
4. 编制至少一项整改或预防措施，指定同部门、启用且具备执行权限的措施责任人。措施责任人不能是复核人。措施截止日不得早于今天或晚于问题截止日，验证日不得早于本轮措施截止日。
5. 提交方案后措施冻结。指定复核人填写意见，通过进入措施执行，退回则恢复方案编制。没有权限或不是指定人员时，不显示可执行按钮，接口同样拒绝操作。
6. 措施责任人从“我的执行措施”进入问题，填写执行证据后完成本人措施。证据应能定位实际记录、检查结果与日期。本版证据为文本，不上传附件。
7. 全部本轮措施完成后，整改责任人填写汇总结果并提交效果验证。
8. 到达最早效果验证日后，复核人独立核对结果，填写证据并关闭问题。时间到达不会自动关闭，不应把“执行完成”直接当成“整改有效”。

## 验证失败或问题复发

效果验证无效时，复核人填写验证证据，进入下一轮原因与方案。关闭后发现问题复发，复核人填写重新开启原因，进入新一轮。之前的措施、完成证据和转换记录保留在详情；历史措施不可编辑，新方案必须重新编制本轮措施。

临时处置原记录保留。每轮原因、方案和执行、验证内容通过“展开记录”查阅；当前详情显示当前轮次。需要改变已经冻结的责任归属时，本版未提供移交流程，应保留原单并建立相关新报告，不应直接修改数据库追踪字段。

## 查询和报告

“质量问题”可按标题或编号查询，按状态筛选，按新报告、截止日或严重度排序，每页十条。“质量统计”按当前数据权限展示总数、未关闭逾期数、多轮整改数以及状态、严重度和来源分布。数据为空时显示真实空状态。

具备导出权限者可下载 JSON 报告，包含问题、全部轮次措施和历史记录，不插入推广内容。导出含业务资料，请核对共享对象。它不是电子签名文件或监管认证报告。

## 管理与常见提示

- 权限代码、导航页面和参数是服务登记资源，只能维护名称、显示顺序、启用状态及有效参数，不能随意新增未实现页面。
- 字典代码与类型创建后不可改变；名称可修改，被问题引用的来源或类别不能删除。
- 系统时区用于业务“今天”和时间显示；已保存的日期不会自动换算。改变时区前应核对团队业务日期的含义。
- 账号重置密码后旧会话失效。个人修改密码需验证当前密码并重新登录。
- 版本过期：刷新详情再操作。验证日未到：完成观察后再提交验证。措施未完成：对应执行人补齐证据。
- 登录连续失败达到限制时等待五分钟；此限制为单服务内存窗口，重启后重置。
