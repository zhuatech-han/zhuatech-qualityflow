# QualityFlow 架构与接口

上海如静知华信息科技有限公司 · [知华科技](https://www.zhuatech.cn/) · 商业咨询微信 zhuatech / zhuatech2。

## 事务与数据模型

同源浏览器通过 Nginx 访问 Spring Boot。认证在 HttpOnly 会话 Cookie 中维护，CSRF 引导返回请求头名与令牌；写接口需要携带该头。账号状态、密码散列、角色及权限每次从数据库核验。

`QualityService` 负责报告、措施和状态转换，`AdminService` 管理系统资源，`Store` 通过 JPA 执行参数绑定查询。对问题行加悲观写锁，校验客户端版本，更新业务变更计数使 JPA 版本递增。同问题并发写串行化；过期版本返回 409。

| 表 | 责任与约束 |
| --- | --- |
| quality_case | 问题当前快照、责任人、轮次、日期、原因、方案及验证；人员和部门外键 |
| corrective_action | 各轮措施、指定执行人、截止日、完成证据与时间 |
| case_event | 追加历史，保存转换前后状态、轮次、操作者和业务证据 |
| mutation_stamp | 问题、账号与请求键唯一；请求指纹检测同键不同内容 |
| account / access_role / role_permission | 账号、角色、功能权限；散列字段不序列化 |
| department / permission / nav_menu | 组织、服务权限目录、受权限约束的导航 |
| dictionary_entry / system_setting | 来源、类别、时区和系统名称 |
| audit_event | 操作、对象、部门和时间，不保存密码与认证载荷 |

`V1__quality.sql` 建立全部结构，`V2__quality_indexes.sql` 增加查询索引和菜单权限外键，`V3__event_text.sql` 扩展业务历史长文本。迁移成功后 Bootstrap 在空库初始化账号与系统目录。JPA `validate` 保证字段映射与实际结构一致。

## 接口目录

| 方法与路径（以 /api 为前缀） | 内容 |
| --- | --- |
| GET /auth/csrf | 匿名读取 CSRF 引导 |
| POST /auth/login | 登录；需要 CSRF |
| GET /auth/me | 实时账号、角色、数据范围、菜单 |
| POST /auth/logout、/auth/password | 退出、验证旧密码后改密 |
| GET /options | 当前范围内启用人员、组织、字典和显示参数 |
| GET /cases | search、status、page（0 起）、size（1–100）、sort（newest/due/severity） |
| POST /cases、PUT /cases/{id}、DELETE /cases/{id}?version=N | 本人报告草稿增改删 |
| GET /cases/{id} | case、actions、events、commands |
| POST /cases/{id}/{command} | 有限业务转换 |
| POST /cases/{id}/actions、PUT /cases/{id}/actions/{aid} | 本轮未送审措施增改 |
| DELETE /cases/{id}/actions/{aid}?version=N | 本轮未送审措施删除 |
| POST /cases/{id}/actions/{aid}/complete | 指定执行人提交证据 |
| GET /cases/{id}/report.json | 受权限控制的 JSON 报告 |
| GET /workbench、/dashboard、/audit | 待办、质量统计和审计 |
| GET /admin/{type} | users/roles/departments/menus/permissions/dictionaries/settings 目录 |
| POST /admin/{type}、PUT /admin/{type}/{id}、DELETE /admin/{type}/{id} | 受保护管理资源维护 |

`/actuator/health` 返回健康状态，仅此 Actuator 端点公开。

命令名为 submit、cancel、begin、analysis、reschedule、submit-plan、approve-plan、reject-plan、submit-evidence、verify、fail-verification、reopen。命令及措施完成输入含 `version`、`requestKey`，请求键为 8–80 位字母、数字、横线或下划线。重试应携带完全相同的原始内容；同键不同内容返回 `IDEMPOTENCY_CONFLICT`。成功重试不重复创建历史，但返回当前详情。创建草稿和管理目录使用版本或唯一约束，不承诺请求键幂等。

日期为 ISO `YYYY-MM-DD`，事件时间为 UTC Instant。方案原因、处置和证据须非空且遵守长度限制；接口不接受任意实体字段。错误统一为 `{ "code": "业务代码" }`，400 表示输入错误，401 为未认证，403 为权限或责任不符，404 为不存在，409 为状态、版本、引用或重试冲突。

## 安全边界

列表、详情、导出、统计采用相同数据范围。ASSIGNED 包括本人参与的历史措施，因此参与者仍能查看相关后续整改；本版不是多租户隔离。复核必须是指定复核人，且不能参与该问题任一历史轮次的报告或执行。审计为事务数据库记录，没有签名或防篡改存储。

业务输出不插入品牌广告；源码署名与自有代码 LICENSE 保留。未提供二进制上传或第三方业务调用。
